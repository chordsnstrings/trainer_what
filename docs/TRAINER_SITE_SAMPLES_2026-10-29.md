## Reusable composition system

- **Seven module families / 55 presentation variants:** hero 10, statement 9, method 10, offers 10, story 8, FAQ 2, contact 6.
- **Ten coherent recipes:** independent public brief, content, tokens, ordered module IDs and a registered scene.
- [Module catalogue](trainer-site-samples/catalog.json) and [selection schema](trainer-site-samples/recipe.schema.json) are copied from the published source. These are prototype composition contracts, not a migration of the production site-builder document.
- Shared renderers assemble semantic HTML; each direction has its own responsive compositions. Scene geometry is procedural and registered in code. AI-authored executable JS/HTML/shaders are outside the contract.
- Controlled scene inputs include color, bounded intensity and scroll/still motion. Cameras are registered presets. The trainer-facing editing/lock/revision UI and Seed integration remain subsequent production work.
- Seed should select a direction from confirmed public facts and approved assets, then compose compatible modules and purpose-written section content. Preserve coherence, factual grounding and manual choices rather than treating module selection as random decoration.

## Motion, assets and fallbacks

Three.js **0.180.0** is bundled locally. Each sample has one lazily created WebGL canvas. Rendering runs on demand as scroll or pointer input changes; it stops offscreen and while the document is hidden. Pixel density is capped, scene resources are disposed, and context-loss handling restores a distinct SVG fallback. Every scene has its own immediate static art; essential content and actions remain semantic HTML. Reduced-motion preferences are honored, with a separate local motion toggle. Native scroll is retained.

Photos are optimized local WebP files. Fonts are locally bundled WOFF2; six OFL notices and the Three.js MIT license are retained. Image provenance is in the sample source's `dist/assets/sources.json`. Photography was visually inspected, unsuitable images replaced, and descriptions corrected. No remote runtime assets, analytics or external API calls are needed. Production trainers must supply their own rights-approved public media.
