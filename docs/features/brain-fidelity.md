# Trainer review of unfamiliar conversations

Status: implemented, release checks in progress, 9 October 2026. Continues the human-evaluation step recorded after shared-Brain PR #53. Earlier chat/motion changes through PR #54 and documentation main `062b492` are deployed; this feature has not yet been verified live.

## Trainer flow

Open **My Brain → Conversation options → Brain review → Compare my replies**, or the detailed Brain workspace's **Compare my replies** tab. Save one to three fictional subscriber/trainer exchanges, the next message, the exact reply you would send, why, and whether human handover is needed. Save this reference before generating a reply. The reference and reason never enter the model input. Situations and references cannot be edited after saving; use a new unfamiliar case when the situation changes.

**Compare with current Brain** makes one bounded supervised-chat model request using the active runtime profile, published rules and communication snapshot, and the fictional conversation. It uses the same coaching decision adapter and version as supervised chat, including forbidden-phrase/output checks. It does not impersonate a real subscriber or load their profile, workout memory or private messages. Numeric/programme and safety checks withhold unsupported outputs. A failed or unknown paid attempt is kept and is not automatically repeated. A repeated click or lost HTTP response reuses the saved attempt; an interrupted in-flight attempt needs operator review. Evaluation tasks never switch to a fallback profile and their usage stays platform-borne setup cost.

The trainer sees shuffled replies A and B: their saved reference and the Brain's reply. Rate **coaching decision**, **tone/wording**, and **use of conversation**, each from 1 to 5. Saving both ratings reveals the sources and locks the scores. The reference may be recognised, so this is a source-hidden paired review, not a scientifically blinded study or proof of human equivalence. Source labels, reasoning, version receipts and usage are omitted from pre-rating responses, including list responses. Generic workspace record/collection endpoints cannot expose the private case or run kinds.

Saved attempts record the Brain release and context digest, model/provider, request settings and budget, supervised-chat prompt, conversation version, safety-policy version, rubric version and actual usage. Only graded, still-independent situations matching the **current** Brain/model configuration enter the current summary. Failed, unfinished and awaiting-rating attempts are counted separately; there is no composite accuracy percentage. Older reviews remain inspectable and an unchanged held-out case can be compared again after a Brain/model version changes. One current attempt per case/version and bounded retention of 100 cases/500 runs limit repeated spend and response size.

## Keeping evaluation separate from teaching

Private cases/runs are excluded from teaching compilation, qualification practice, subscriber context and bootstrap. The owner must attest to fictional, non-identifying data; contact/account pattern screening cannot guarantee anonymisation. Known communication examples, interview/source text and practice questions are checked for exact/near lexical overlap before case creation/generation and when computing summaries. This does not prove semantic independence from every piece of teaching or pretraining. The scan is bounded to 2,000 source records and 4 MB of stored material; exceeding it stops the review rather than silently omitting material.

After rating, **Teach from this review** saves only the trainer's explicit corrected reply and lesson as a normal interview note. The situation is atomically retired from the evaluation set, all its earlier ratings remain recorded, and none contribute to the current independent-case summary. The teaching note joins the normal compilation, rule review and publication flow; saving a correction never publishes or qualifies a Brain. Keep other cases untouched to compare later releases. Separately added overlapping teaching also removes a case from the current summary.

This first evaluation surface covers written supervised chat. It does not measure the automatic action selector, intake/calls, programme/nutrition explanations or narration, and does not requalify any workspace. Cross-channel human grading, real-provider/account acceptance and physical-phone audio are separate follow-ups. No measured fidelity percentage is claimed from software tests or interview coverage.

## Verification

The API/domain tests cover fictional exchange validation, private-data/known-case screening, tenant and role boundaries, generic-record concealment, reference-answer exclusion, immutable ratings and source reveal, version-separated summaries, actual usage records, concurrent request deduplication, explicit teaching/retirement, later teaching contamination and invalid/safety output withholding. The conversation browser journey exercises actual API/database saves, generation with an isolated provider, ratings/reveal, correction-to-teaching and layouts at 1280, 390 and 320 pixels. CI results and deployment evidence are recorded in the handoff when complete.
