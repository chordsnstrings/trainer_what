## Trainer flow

Open **My Brain → Conversation options → Brain review → Compare my replies**, or the detailed Brain workspace's **Compare my replies** tab. Save one to three fictional subscriber/trainer exchanges, the next message, the exact reply you would send, why, and whether human handover is needed. Optionally add up to three older fictional exchanges, treated as 20 days earlier, to test recall or a later correction. Recent exchanges and the new message are bounded to 2,400 characters, older exchanges to 4,000. Save this reference before generating a reply. The reference and reason never enter the model input. Situations and references cannot be edited after saving; use a new unfamiliar case when the situation changes.

**Compare with current Brain** makes one bounded supervised-chat model request using the active runtime profile, published rules and communication snapshot, and the fictional conversation. It uses the same coaching decision adapter and version as supervised chat, including forbidden-phrase/output checks. It does not impersonate a real subscriber or load their profile, workout memory or private messages. Numeric/programme and safety checks withhold unsupported outputs. A failed or unknown paid attempt is kept and is not automatically repeated. A repeated click or lost HTTP response reuses the saved attempt; an interrupted in-flight attempt needs operator review. Evaluation tasks never switch to a fallback profile and their usage stays platform-borne setup cost.

The trainer sees shuffled replies A and B: their saved reference and the Brain's reply. Rate **coaching decision**, **tone/wording**, **use of conversation**, **explanation/reasoning**, and **knowing when to ask or defer**, each from 1 to 5. Reasoning is judged from the visible reply; hidden rationale is only revealed afterwards. Older three-dimension ratings remain readable, with missing scores left unscored. Saving both ratings reveals the sources and locks the scores. The reference may be recognised, so this is a source-hidden paired review, not a scientifically blinded study or proof of human equivalence. Source labels, reasoning, version receipts and usage are omitted from pre-rating responses, including list responses. Generic workspace record/collection endpoints cannot expose the private case or run kinds.

Saved attempts record the Brain release and context digest, model/provider, request settings and budget, supervised-chat prompt, conversation version, safety-policy version, rubric version and actual usage. Only graded, still-independent situations matching the **current** Brain/model configuration enter the current summary. Failed, unfinished and awaiting-rating attempts are counted separately; there is no composite accuracy percentage. Older reviews remain inspectable and an unchanged held-out case can be compared again after a Brain/model version changes. One current attempt per case/version/approach and bounded retention of 100 cases/500 runs limit repeated spend and response size.

With older exchanges, **Compare with recent messages only** explicitly makes a second bounded call using the same rules, model and prompt, but omits older context. The default approach uses the exact production selector: up to 12 recent turns plus up to two relevant older excerpts, at most six whole recalled turns and 4,000 characters. The fictional clock is fixed at case creation, so a delayed comparison does not age away its context. Reference answers never participate in selection.

The current Brain summary uses recall attempts only. A separate comparison shows ratings only when both approaches have been rated on the same case and current configuration. Each dimension shows its own paired count; missing scores are never zeroes. Baseline failures, unfinished attempts and missing ratings remain visible. Teaching retirement removes both approaches from independent summaries. These small, potentially recognisable human comparisons measure neither statistical significance nor an accuracy percentage.

## Keeping evaluation separate from teaching

Private cases/runs are excluded from teaching compilation, qualification practice, subscriber context and bootstrap. The owner must attest to fictional, non-identifying data; contact/account pattern screening cannot guarantee anonymisation. Known communication examples, interview/source text and practice questions are checked for exact/near lexical overlap before case creation/generation and when computing summaries. This does not prove semantic independence from every piece of teaching or pretraining. The scan is bounded to 2,000 source records and 4 MB of stored material; exceeding it stops the review rather than silently omitting material.

After rating, **Teach from this review** saves only the trainer's explicit corrected reply and lesson as a normal interview note. The situation is atomically retired from the evaluation set, all its earlier ratings remain recorded, and none contribute to the current independent-case summary. The teaching note joins the normal compilation, rule review and publication flow; saving a correction never publishes or qualifies a Brain. Keep other cases untouched to compare later releases. Separately added overlapping teaching also removes a case from the current summary.

This first evaluation surface covers written supervised chat. It does not measure the automatic action selector, intake/calls, programme/nutrition explanations or narration, and does not requalify any workspace. Cross-channel human grading, real-provider/account acceptance and physical-phone audio are separate follow-ups. No measured fidelity percentage is claimed from software tests or interview coverage.
